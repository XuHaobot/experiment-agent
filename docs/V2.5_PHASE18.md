## 2. 核心架构与新增组件

### 2.1 候选实验组合生成引擎 (`backend/domain/exploration.py`)
拒绝“单一最优实验”的黑盒建议，生成 4 种互补范式的候选实验组合：
* **Type A (EXPLOIT · 主假说深挖)**：围绕已知最高性能邻域进行细粒度微调与极值定位；
* **Type B (DISCRIMINATE · 假说判决)**：专门设计用于区分相互矛盾的竞争性假说（如判决“高阶过平滑” vs “学习率拓扑失配”）；
* **Type C (EXPLORE · 盲区探测)**：跳跃至未采样的参数空间未知区域；
* **Type D (REPLICATE · 稳定性排查)**：多随机种子复现关键拐点，量化统计误差条与复现置信度。

### 2.2 认识论价值与假说区分度矩阵 (Epistemic Value & Discrimination Matrix)
* **Epistemic Value (认识论价值)**：
  $$\text{Epistemic Value} = f(\text{Info Gain}, \text{Uncertainty Reduction}, \text{Discrimination Power}, \text{Novelty}, \text{Reproducibility}) - \text{Cost} - \text{Risk}$$
  以 `HIGH` / `MEDIUM` / `LOW` 定性呈现，并附带完整可解释依据，拒绝伪科学概率数字。
* **Hypothesis Discrimination Matrix**：
  明确列出各候选实验在 $H_1, H_2, H_3$ 假说下的不同预测表现，帮助科研人员优先选择**能一次性否定竞争假说的判决性实验**。

### 2.3 伪探索与重复实验检测 (Pseudo-Exploration Detection)
* 自动分析候选参数与历史 Runs 的多维欧氏/归一化距离；
* 当参数落在已密集采样（$\ge 3$ 次）的局部饱和区域且无其他新颖变量时，自动标记 `is_pseudo_exploration: True` 并给出警告提示，防止在局部陷入无意义的微小变体调参循环。

### 2.4 假说认知修剪顾问 (Epistemic Pruning Advisor)
* 自动统计各假说的正向与反面证据数量；
* 状态机支持：`ACTIVE`, `WEAKENED`, `SUPPORTED`, `REFUTED`, `STALE`, `NEEDS_MORE_EVIDENCE`；
* **核心学术原则**：系统生成资源倾斜建议（如对被反驳多次的假说降低实验预算），但**绝对不自动物理删除任何假说**，决策权 100% 留给科研人员。

### 2.5 人工审批门禁与因果血缘 (HITL Approval Gate & Lineage)
* 科研人员在 Explore 界面一键批准候选实验后，系统在 `data/records/` 创建正式 Experiment 草稿，建立 `Project -> Hypothesis -> Candidate -> Experiment` 的完整双向血缘。

## 3. REST API 接口定义

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/projects/{id}/exploration/candidates` | 获取探索引擎生成的多范式候选实验组合 (A, B, C, D) 与动态探索天平建议 |
| `GET` | `/api/projects/{id}/exploration/discrimination` | 获取竞争性假说区分度矩阵 (Hypothesis Discrimination Matrix) |
| `GET` | `/api/projects/{id}/exploration/pruning` | 获取假说认知修剪与资源优化顾问建议 (非破坏性) |
| `POST` | `/api/projects/{id}/exploration/approve` | 科研人员批准候选实验，生成正式实验草稿并建立血缘关系 |

  - 一键审批生成正式实验草稿。
* 在 `frontend/src/views/ProjectDetailView.vue` 导航栏中接入「科学探索 (Explore)」选项卡。
