# ResearchOS V2.4+ 长期技术演进与 Backlog 规划

本文档记录在 V2.3 验收收敛阶段明确延后（Deferred to V2.4+）的技术特性与生态规划。

---

## 1. 延后功能清单 (Deferred Backlog)

| 模块 / 特性 | 规划阶段 | 延后原因与前置条件 |
|---|---|---|
| **MCP (Model Context Protocol) Server** | V2.4 | V2.3 阶段 ToolRegistry 已满足全部本地工具拦截与风控审计需求，避免引入额外 MCP 守护进程。 |
| **PaperQA2 全文深度解析** | V2.4 | 当前元数据检索与摘要提取已覆盖文献先验需求，全文 Embedding 与重排序待用户有大规模 PDF 研读需求时接入。 |
| **多用户协作与云端权限** | V2.5 | 保持当前 Local-First 单机桌面工作台定位，优先保障科研人员个人使用体验。 |
| **在线 JupyterLab 深度嵌入** | V2.4 | 当前 Notebook Import/Export 与 Artifact 解析已足够，无需将整个 Web IDE 强行内嵌。 |
| **物理仪器与自动化实验硬件控制** | V3.0 | 属于湿实验/硬件自动化范畴，远期规划。 |
| **Multi-Agent Swarm 协同网络** | V2.5 | 当前单一强科研 Agent 配合 ToolRegistry 已具备高确定性，多智能体通信开销与不可控性较高。 |

---

## 2. 下一阶段核心建议

1. **文献全文研读与 PDF 本地证据切片**；
2. **多数据表交叉关联与复杂统计分析向导**；
3. **实验方案的自动化代码模板生成与一键调试**。
