# ResearchOS V2.6 真实科研工作流全景指南 (Product Workflow)

> **版本**：V2.6.0-WIP (Product Hardening)  
> **定位**：Local-First Personal Research Workspace (个人科研工作台)  
> **核心原则**：连续、透明、可解释、严谨证据支撑、100% 保护科研人员个人笔记与数据隐私。

---

## 一、真实科研端到端工作流闭环

```text
                  1. Research Question (核心科学问题)
                             │
                             ▼
                  2. Hypothesis (待检验科研假说)
                    /                   \
                   ▼                     ▼
          3. Evidence Ledger       4. Active Exploration
        (支持 vs 反驳证据天平)      (Type A/B/C/D 候选组合)
                   \                     /
                    ▼                   ▼
                  5. Experiment (实验方案与脚本)
                             │
                             ▼
                  6. Experiment Run (多次运行与参数扫描)
                             │
                             ▼
                  7. Dataset & Analysis (DuckDB 结构化分析)
                             │
                             ▼
                  8. Artifact (图表/报告/模型血缘追踪)
                             │
                             ▼
                  9. Conclusion (双向事实沉淀与假说更新)
                             │
                             ▼
                 10. Research Memory & Diary
                   (认知演进时间线 + 每日反思)
                             │
                             ▼
                 11. Obsidian Vault Bridge
                   (双向导出 + 长期知识互补)
```

## 二、关键操作步骤详解

### 步骤 1：确立科学问题与假说 (Question → Hypothesis)
- 在课题详情页创建清晰的研究问题（如“动态图拓扑邻域大小 $k$ 如何影响流形平滑性与模型泛化？”）；
- 提出可检验假说 $H_1$。系统自动初始化假说状态为 `ACTIVE` 或 `TESTING`。

### 步骤 2：多范式科学探索推荐 (Active Exploration)
- 进入「🧭 科学探索」面板，系统自动执行：
  1. 扫描已知事实与反面矛盾运行；
  2. 探测超参数盲区（如 $k \in [21, 29]$ 未采样）；
  3. 生成 Type A (Exploit), Type B (Discriminate), Type C (Explore), Type D (Replicate) 候选组合；
  4. 给出“Why this?”通俗科学依据与假说区分度矩阵；
  5. 自动警示密集饱和区内的“伪探索”微调。
- 科研人员审阅后一键批准，生成正式实验草稿。

### 步骤 3：实验执行与参数扫描 (Experiment → Runs)
- 在实验设计中运行 Python 脚本或从外部 CSV / MLflow 导入实验遥测；
- 每次执行生成独立的 `ExperimentRun` 记录，包含参数字典、指标（Accuracy, Loss, F1）、运行耗时与标准输出。

### 步骤 4：多运行横向对比 (Run Comparison)
- 勾选多个运行实例（如 `Run #01`, `Run #02`, `Run #03`），一键唤起横向对比矩阵；
- 直观查看自变量差异、指标峰值与极值拐点坐标。

### 步骤 5：数据分析与产物生成 (Dataset → Analysis → Artifact)
- 导入实验遥测 CSV 至内置 DuckDB；
- 执行参数敏感度分析与折线图生成，自动记录 SHA256 与前向因果血缘（Artifact $\to$ Run $\to$ Experiment）。

### 步骤 6：证据提炼与结论沉淀 (Evidence → Conclusion)
- 将最优运行或文献切片标记为假说的支持证据 (Supporting Evidence)；
- 将性能回落或异常中断标记为反面证据 (Contradicting Evidence)；
- 沉淀科学结论（Conclusion），系统自动更新假说置信充分度与认知天平。

### 步骤 7：记录科研日记与会话 (Research Diary & Session)
- 每日记录灵感猜测与直觉反思（`USER_BELIEF`），永久留存个人心路历程；
- 一轮工作结束时生成 Research Session 概要，随时回顾“这轮科研工作探索了什么”。

### 步骤 8：无缝投影至 Obsidian (Obsidian Vault Bridge)
- 一键导出至 Obsidian 个人知识库；
- 包含标准 YAML Frontmatter、10 级 `epistemic_status` 与 `[[Wikilinks]]`；
- 段落隔离技术（`<!-- RESEARCHOS:START -->`）100% 保护科研人员在 Obsidian 中撰写的个人手记。

---

## 三、真实产品质量保障

- **零幻觉与零虚构**：所有推荐与 Memory 回答必须有具体 Run ID 或文献来源支持；
- **本地优先与隐私防护**：敏感数据未经验证绝不上传云端，本地 Ollama 驱动离线可用；
- **全流程可解释与撤销**：AI 绝不擅自物理删除任何假说或历史记录。
