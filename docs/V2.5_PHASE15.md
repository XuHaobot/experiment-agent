> **交付日期**：2026-08-31  
> **测试状态**：18/18 PASS (100% 全绿，无任何既有功能回归)

---

## 1. 核心目标回顾与完成情况

在 Phase 15 中，我们正式确立了 **Personal Research Space** 的核心技术底座：**将数据隐私决策权交还给科研人员**。
* **不再将 Prompt 盲目发往云端**；
* **引入三级数据隐私网关 (`ALLOW` / `ASK` / `DENY`)**，在模型调用前进行前置硬性安全拦截；
* **统一抽象 `LLMProvider` 与 `LLMGateway`**，原生接入本地离线大模型引擎（Ollama），支持纯本地零外网泄露运行。

## 2. 修改与新增文件清单

### 2.1 新增模块与文件
* `backend/llm/base.py`：`LLMProvider` 抽象基类、`ProviderCapabilities`、`ChatMessage`、`ChatResponse`、`RoutingPolicy`。
* `backend/llm/providers/ollama.py`：本地 Ollama 驱动适配器（连通性测试、`/api/tags` 模型列表、同步对话与流式输出）。
* `backend/llm/providers/openai_compatible.py`：标准 OpenAI 兼容驱动（DeepSeek / Qwen / 通义千问等）。
* `backend/llm/providers/mock.py`：确定性 Mock 驱动，用于离线环境与自动化测试套件。
* `backend/llm/providers/__init__.py`：提供商导出。
* `backend/llm/gateway.py`：`LLMGateway` 核心网关（提供商注册、健康探测、路由策略、前置隐私门禁拦截）。
* `backend/llm/context.py`：`ResearchContext`、`ContextItem`、`ContextPlanner`（结构化上下文打包与分级来源追踪）。
* `backend/llm/__init__.py`：LLM 子系统主入口。
* `backend/security/classification.py`：数据分级语义 (`PUBLIC`, `INTERNAL`, `SENSITIVE`, `RESTRICTED`) 与正则/启发式分类器。
* `backend/security/privacy_gateway.py`：`PrivacyGateway`（ALLOW / ASK / DENY 决策、数据脱敏、工单创建与核验、硬阻断抛出 `PrivacyViolationError`）。
* `backend/security/audit.py`：隐私合规与 AI 访问审计日志器（记录至 `data/audit/privacy_audit.jsonl`，不存敏感原文）。
* `backend/security/__init__.py`：安全子系统主入口。
* `tests/test_v25_phase15.py`：涵盖 9 个核心场景的 Phase 15 验收测试套件。

### 2.2 修改文件
* `src/llm_client.py`：升级 `LLMClient.call_llm` 优先通过 `LLMGateway` + `PrivacyGateway` 流转，保持向下兼容。
* `backend/domain/next_experiment.py`：补充 `logger` 实例定义，增强异常回退鲁棒性。
* `backend/main.py`：注册 `/api/llm/*` 与 `/api/privacy/*` 9 个 RESTful API 端点。
* `frontend/src/components/LlmSettings.vue`：新增 Local AI (Ollama) 连通性测试、模型刷新与 Privacy 策略选择面板。

## 3. REST API 接口定义

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/llm/providers` | 列出所有 Provider、健康状态与活跃提供商 |
| `GET` | `/api/llm/providers/{id}/health` | 实时探测指定 Provider 连通性 |
| `GET` | `/api/llm/providers/{id}/models` | 获取指定 Provider 本地已拉取的模型清单 |
| `POST` | `/api/llm/providers/select` | 切换当前活跃 Provider 与 RoutingPolicy |
| `POST` | `/api/llm/chat` | 经过 Privacy Gateway 检查后的安全模型对话 |
| `POST` | `/api/privacy/check` | 预先评估文本或 Context 的数据隐私分级与放行决策 |
| `POST` | `/api/privacy/authorize` | 用户人工授权或拒绝敏感上下文审批工单 (Ticket) |
| `GET` | `/api/privacy/audit` | 查看本地安全审计日志 (最近 50 条) |
| `GET` | `/api/privacy/config` | 查看当前全局隐私规则与策略配置 |
| `POST` | `/api/privacy/config` | 更新全局隐私策略 (`LOCAL_ONLY`, `LOCAL_PREFERRED`, `CLOUD_ALLOWED`) |

## 4. 数据流与隐私门禁流水线 (Data Flow)

```text
科研人员 / Agent 提出请求
           │
           ▼
┌──────────────────────────────────────┐
│  Context Planner (构建 ResearchContext) │
│  • 标注每个 Item 的 source_id / type   │
│  • 初始标记 PUBLIC / SENSITIVE / RESTRICTED │
└──────────────────┬───────────────────┘
                   │
                   ▼
┌──────────────────────────────────────┐
│       Privacy Gateway 检查器         │
└──────────────────┬───────────────────┘
                   │
    ┌──────────────┼──────────────┐
    ▼              ▼              ▼
 [ALLOW]         [ASK]          [DENY]
 (直接放行)   (生成审批工单)  (硬性阻断并告警)
    │              │              │
    │        [用户点击批准]        └──> 抛出 PrivacyViolationError
    │              │                   (LLM Provider 绝不被调用)
    ▼              ▼
┌──────────────────────────────────────┐
│  安全脱敏流水线 (Data Sanitizer)     │
│  • 抹除本地机器绝对路径 (/Users/...)   │
│  • 抹除真实 API Key / 租户 ID        │
└──────────────────┬───────────────────┘
                   │
                   ▼
┌──────────────────────────────────────┐
│  LLM Gateway (路由至活跃 Provider)    │
│  • Local: Ollama (11434)             │
│  • Cloud: OpenAI-Compatible (BYOK)   │
└──────────────────┬───────────────────┘
                   │
                   ▼
┌──────────────────────────────────────┐
│  Audit Logger (记录至 jsonl 审计文件) │
└──────────────────────────────────────┘
```
