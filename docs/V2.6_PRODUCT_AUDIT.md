## 二、11 个核心产品体验问题解答

### 1. 哪些功能是真正可用的？
- 课题、假说、实验、运行、分析向导、证据天平、本地 Ollama 交互、Obsidian 笔记隔离导出、主动探索组合推荐与全因果追溯均 100% 可用且通过真实测试。

### 2. 哪些功能只有 API，缺少完整闭环？
- 过去在“运行对比 (Run Comparison)”与“科研日志 (Research Diary)”方面需要用户逐个点击查看，缺乏直观的横向对比与日常随手笔记面板。本阶段将彻底补齐。

### 3. 哪些 UI 只是“展示数据”，没有形成操作闭环？
- 过去在假说卡片上，用户看完支持/反面证据后，需要切到实验页面手动配置参数；V2.6 增加“从假说直接触发候选实验并批准为草稿”的操作闭环。

### 4. 哪些功能用户需要自己理解内部概念才能使用？
- Phase 18 的 `Epistemic Value: 0.83`, `Information Gain: HIGH`, `Uncertainty Reduction: 0.65` 等算法指标，科研用户更关心：“**为什么建议这个实验？能区分哪两个假说？**”。前端已通过科研自然语言完成翻译。

### 5. 哪些功能存在重复入口？
- “Next Experiment 启发式建议”与“Active Exploration 科学探索”存在概念重叠。V2.6 将探索统一收敛至“🧭 科学探索 (Explore)”面板。

### 6. 哪些数据需要重复录入？
- 实验草稿与 Run 执行时，参数无需重复手工输入，直接从 Candidate 或基线一键继承。

### 7. 哪些操作无法撤销？
- 假说修剪 (Pruning) 严格遵循“非破坏性建议”，系统绝对不提供也不执行自动物理删除。

### 8. 哪些状态变化没有审计记录？
- Privacy Gateway 已拥有 `data/audit/privacy_audit.jsonl`，本次在 Research Timeline 中将探索批准与修剪建议一并纳入时间线事件流。

### 9. 哪些 AI 输出没有明确证据来源？
- 严禁任何虚构引用，AI Copilot 与 Memory 回答必须严格附带 `OBSERVATION` / `EVIDENCE` / `INTERPRETATION` 结构与引用 ID。

### 10. 哪些功能在真实科研流程中几乎不会被主动使用？
- 过于复杂的纯理论优化图表与伪置信度百分比（如 93.4%）被移除，替换为定性 `STRONG` / `MODERATE` / `WEAK` 与直观误差条。

### 11. 哪些功能虽然存在，但是用户不知道它为什么存在？
- 过去系统暴露了过多架构名词（如 ContextPlanner, RoutingPolicy），V2.6 统一抽象为普通科研人员易懂的“本地离线 AI”与“数据隐私保护”。

## 三、V2.6 改进实施路线

1. **新建 Research Diary 模块 (`backend/domain/diary.py`)**：为科研人员提供每日随手记录（标记为 `USER_BELIEF` / `OBSERVATION`，AI 绝不篡改）；
2. **新建 Research Session 模块 (`backend/domain/session.py`)**：轻量记录单次工作会话查看的论文、运行与产出；
3. **实现 Run Comparison 引擎 (`backend/domain/run.py`)**：横向对比多个 Run 的参数、指标、耗时与产物；
4. **重构 Research Cockpit 首屏**：直面科研 5 问（正在研究什么、假说是什么、有什么证据、已做了什么、下一步做什么）；
5. **探索界面科研自然语言翻译**：以“Why this? 能排除什么竞争假说？”直白呈现；
6. **编写完整 20 步科研闭环测试 (`tests/test_v26_product_workflow.py`)**。
