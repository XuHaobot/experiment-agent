# ResearchOS V2.3 — 全项目只读审计报告 (Pre-Audit)

> **审计基准版本**：ResearchOS V2.2 (Open Research Stack)  
> **审计范围**：`backend/domain/`, `backend/integrations/`, `backend/agent/`, `backend/main.py`, `src/graph/`, `frontend/`, `tests/`, `data/`  
> **核心目标**：逐一审查 15 个科研实体链路与数据一致性问题，确认数据真实性与无硬编码/伪造问题。

---

## 15 个核心问题专项审计

### Q1: `Project` 是否可以真实关联所有科研实体？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `data/projects/{project_id}.json` 真实持久化存储并关联：`questions`、`experiment_ids`、`paper_ids`、`dataset_ids`。
  - `Hypothesis`、`Run`、`Artifact`、`Conclusion`、`Analysis` 均以 `project_id` 为外键索引并按需动态关联。
  - 读取与写入均经过 `backend/domain/project.py` 中的 `get_project`、`update_project`、`_save_project` 执行真实本地文件 I/O。

### Q2: Paper 保存以后，`Project → Paper` 是否能够反向查询？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `save_paper_to_project` 在 `backend/domain/paper.py` 中将文献写入 `data/papers/{paper_id}.json` 并将 ID 追加至 `project["paper_ids"]`。
  - `list_project_papers(project_id)` 与 `GET /api/projects/{project_id}/papers` 遍历对应 paper_ids 并返回完整实体字典。

### Q3: Paper 能否真正形成 Evidence？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `backend/domain/conclusion.py` 中 `VALID_EVIDENCE_TYPES` 包含 `"paper"`。
  - `create_conclusion` 接受 `evidence_refs: [{"type": "paper", "id": paper_id, "snippet": "..."}]` 并持久化记录为文献证据源。

### Q4: Evidence 能否支持 Hypothesis？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `Conclusion` 实体包含 `hypothesis_id` 与 `evidence_refs`，明确记录该假说所依赖的证据清单；
  - `src/graph/builder.py` 自动构建 `Conclusion -> SUPPORTS -> Hypothesis` 和 `Evidence -> SUPPORTS -> Conclusion` 拓扑关系。

### Q5: Hypothesis 是否能进入 Experiment？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `Experiment` 实体包含 `hypothesis_id` 字段；
  - `src/graph/builder.py` 建立 `Hypothesis -> TESTED_BY -> Experiment` 关系，支持从实验反查目标假说。

### Q6: Experiment 是否能产生 Run？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `backend/domain/run.py` 中 `create_run` 接受 `experiment_id`，生成具备 `id` (run_xxx)、`experiment_id`、`actual_parameters`、`metrics`、`status`、`created_at` 的物理实例并存储于 `data/runs/{run_id}.json`。

### Q7: Dataset 实体是否落地真实物理文件与校验和？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `backend/domain/dataset.py` 中 `create_dataset_from_csv` 写入真实 CSV 文件至 `data/datasets/{dataset_id}.csv`，计算 MD5 `checksum`，提取行列数，并将元数据存入 `data/datasets/{dataset_id}.json`。

### Q8: DuckDB / 本地 SQL 引擎是否执行真实查询与聚合？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `backend/integrations/data/duckdb.py` 对真实 CSV 物理文件建立 View 并执行 SQL 计算（如 `GROUP BY`, `AVG`, `ORDER BY`），无 Mock，无写死结果，支持 DuckDB 及 Python SQLite 内存引擎自动降级。

### Q9: Dataset 分析结果能否沉淀为 Evidence？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `VALID_EVIDENCE_TYPES` 包含 `"dataset"`；
  - `Evidence` 引用格式：`{"type": "dataset", "id": dataset_id, "snippet": "A mean=10.47, B mean=15.33"}`，完全支持数据依据追溯。

### Q10: 实验执行 (Run) 是否产生真实 Artifact？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `backend/domain/artifact.py` 中 `create_artifact` 持久化资产至 `data/artifacts/{project_id}/{artifact_id}.json` 与实体内容文件，绑定 `source_record_id` (即 `run_id`)、`mime_type`、`content_hash`。

### Q11: Artifact 能否形成 Evidence 并被 Conclusion 引用？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `Conclusion` 支持引用 `{"type": "artifact", "id": artifact_id, "snippet": "Optimal curve peak at k=20"}`；
  - 数据流形成完整链条：`Dataset -> Experiment -> Run -> Artifact -> Evidence -> Conclusion`。

### Q12: Conclusion 能否推演出 NextExperiment？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `backend/domain/next_experiment.py` 加载当前项目的全部历史 Runs、Conclusions 与 Research State，推演下一阶段高信息增益候选实验，并明确附带 `why` 与 `uncertainty_addressed` 论据。

### Q13: Research Graph 是否支持全流程双向回溯？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `src/graph/builder.py` 与 `backend/main.py` 的 `/api/projects/{project_id}/graph/trace/{node_id}` 支持从 Conclusion 节点多跳递归回溯其前置证据、Artifact、Run、Experiment、Hypothesis、Paper 与 Project，同时支持前向探索 Next Action。

### Q14: Research Memory 是否能准确感知事实并拒绝未验证事实（无幻觉）？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - `backend/domain/memory.py` 动态聚合读取本地持久化的 `papers`, `datasets`, `hypotheses`, `runs`, `artifacts`, `facts`；
  - 在无对应 Runs/Evidence 时，严谨返回 `grounding_level = "UNSUPPORTED"` 并明确指出“目前不能证明，尚未找到已完成的实验运行 (Run)”，杜绝 LLM 凭空臆造。

### Q15: 外部文献 Provider (OpenAlex / arXiv / S2) 是否具备离线容错与降级？
- **审计结论**：**[REAL - 真实可用]**
- **代码与存储依据**：
  - 适配器在 `backend/integrations/literature/` 中统一捕获网络超时与异常，配合本地 TTL 内存缓存，在离线或外部 API 不可用时返回结构化错误提示，绝不导致后端崩溃或虚构论文数据。
