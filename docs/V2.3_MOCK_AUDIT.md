# ResearchOS V2.3 — Mock & Fake Data 专项审计报告

> **审计基准**：扫描全项目所有代码与数据文件，确保不存在冒充真实科研指标/数据的危险 Mock。

---

## 1. 扫描与分类规则

- **SAFE (安全)**：
  - 单元测试与端到端自动化测试中的测试 Fixture、临时目录与模拟断网场景（位于 `tests/`）；
  - 属于正常测试桩代码。
- **DEMO_ONLY (演示标记)**：
  - 前端输入框的 `placeholder` 示例文字（例如输入框提示“例如：dynamic graph convolutional networks”）；
  - 明确标注为用户输入占位符，不参与业务逻辑与数据存储。
- **DANGEROUS (危险)**：
  - 业务逻辑或 API 中伪造计算结果、虚构 GPU/Token 占用、硬编码随机准确率或冒充真实文献。
  - **红线要求：DANGEROUS 数量必须为 0**。

## 3. 核心领域模块数据真实性验证

1. **Python 沙箱与数据分析 (`data_agent.py`)**：
   - 真实调用 RestrictedPython AST 编译器执行代码，计算 `numpy`/`pandas` 真实结果与 Base64 PNG 图表；
2. **DuckDB 分析引擎 (`duckdb.py`)**：
   - 真实对 `data/datasets/*.csv` 文件执行 SQL 语法解析与数据聚合；
3. **文献引擎 (`openalex.py`, `arxiv.py`, `semantic_scholar.py`)**：
   - 真实请求官方公开 REST/Atom 接口，离线时诚实返回“文献源不可用”，严禁虚构论文；
4. **科研记忆 (`memory.py`)**：
   - 严格基于已记录的真实 Runs / Conclusions 进行汇总，无依据时明确标记 `UNSUPPORTED`。
