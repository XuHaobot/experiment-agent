## 1. 产品定位与核心决策 (Product Decisions)

```text
┌─────────────────────────────────────────────────────────────┐
│                 ResearchOS (SSOT Layer)                     │
│  结构化科研执行层：Project, RQ, Hypothesis, Experiment,      │
│  Run, Dataset, Analysis, Evidence, Conclusion, Artifact     │
└──────────────────────────────┬──────────────────────────────┘
                               │
                      Vault Bridge 投射
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 Obsidian (Knowledge Layer)                  │
│  个人知识思考层：自由笔记, 灵感, 双链图谱 (Graph View),     │
│  Markdown + YAML Frontmatter + [[Wikilinks]]                │
└─────────────────────────────────────────────────────────────┘
```

1. **非双数据库同步模型**：拒绝双向 DB 同步。ResearchOS 是科研结构化真相源 (SSOT)，Obsidian 是科研人员本地自由思考和知识网络的投射空间。
2. **段落隔离与个人笔记绝对保护**：
   - 托管内容封装在 `<!-- RESEARCHOS:START -->` 与 `<!-- RESEARCHOS:END -->` 之间；
   - 用户在文件下半部分（如 `## My Notes` / `## My Thoughts`）书写的任何个人反思与未成熟观点，在后续重新同步或导出时**100% 保持完好，绝不被覆盖**。
3. **稳定实体 ID 链接**：使用 `[[H-001]]`、`[[EXP-001]]`、`[[ev_pdf_...]]`、`[[conc_...]]` 等稳定 ID 作为 Wikilinks 锚点，避免因实体标题修改而破坏 Obsidian 双链图谱。
4. **Epistemic Status (认识论状态) 预留**：所有 Markdown 的 YAML Frontmatter 均显式预留 `epistemic_status` (`PROJECT`, `OBSERVATION`, `HYPOTHESIS`, `EXPERIMENT`, `EVIDENCE`, `CONCLUSION`, `FACT`, `USER_BELIEF`)，为未来 Research Memory 2.0 奠定无缝演进基础。
5. **合规与隐私隔离**：导出到 Obsidian Vault 的文件绝不自动 Embedding，也绝不自动绕过 Phase 15 的 `Privacy Gateway` 发往云端 LLM。

## 4. REST API 接口定义

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `POST` | `/api/projects/{id}/vault/preview` | 预览导出计划，返回待新建、待更新、已跳过与实体统计 |
| `POST` | `/api/projects/{id}/vault/export` | 执行无损导出并生成 YAML Frontmatter、Wikilinks 与 manifest |
| `POST` | `/api/projects/{id}/vault/reconcile` | 检查 Vault 文件状态 (`UNCHANGED`, `USER_MODIFIED`, `CONFLICT`) |
