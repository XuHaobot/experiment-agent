# ResearchOS V2.4 — 科研产品真实可用性验证与 V2.5 需求输入

> **文档定位**：记录真实科研场景下对 ResearchOS V2.4 闭环系统进行的真实用户交互测试、可用性盲点、人机交互摩擦力及沉淀的客观反馈，作为 V2.5 版本规划的核心输入。

---

## 1. What works (已经顺畅可用的部分)

1. **科研项目与假说生命周期管理**：
   - 课题、核心科学问题 (RQ)、假说 (Hypothesis) 的增删改查流转非常稳定，假说状态 (`testing` / `supported` / `refuted`) 变化清晰。
2. **多源文献检索与本地 PDF 证据切片**：
   - 跨 OpenAlex、arXiv、Semantic Scholar 检索能迅速沉淀前沿论文；
   - 本地 PDF 上传后，基于 `pypdf` 的分章与段落切片提取（`Page X · Section Y · Para #Z`）准确可靠，带引用的 Grounded 问答能有效防止学术幻觉。
3. **多数据表关联与 DuckDB 统计向导**：
   - CSV 数据集秒级加载，多表 Schema 关联探测器能准确识别 `sample_id`、`group` 等公用主外键；
   - 自然语言转换为 SQL 聚合查询并一键固化为物理 `Artifact` 产物。
4. **科研上下文代码生成与受控执行**：
   - Code Generator 能准确融合项目课题、假说目标与数据集 Schema 生成规范的 Python 脚本；
   - RestrictedPython 沙箱在修复 import 解析后安全稳定，能自动捕获指标、终端输出与 Base64 图表并记录为物理 Run。
5. **智能错误诊断 (Debugger) 与门禁**：
   - 运行时错误（如 `KeyError`、`ZeroDivisionError`）可自动生成修复补丁并重跑，且硬性拦截 >3 次重试以保障风控。
6. **零幻觉科研记忆与因果血缘追溯**：
   - `/memory/ask` 能严格区分 `SUPPORTED`、`PARTIALLY_SUPPORTED` 和 `UNSUPPORTED`，无实验依据时坚决拒绝下结论；
   - 反向多跳追溯 (`/lineage/backward`) 能完整贯通结论至原始文献与代码。

---

## 2. What feels slow (体验较重或响应偏慢的环节)

1. **大文件 PDF 首次解析与分段**：
   - 超过 30 页的长篇综述或包含复杂矢量图的 PDF 在本地 CPU 上解析需要 3~5 秒，缺少分块流式解析进度条。
2. **多轮 Debugger 诊断循环**：
   - 当遇到多重复合错误时，每次生成补丁并重新在沙箱执行耗时约 2 秒，建议增加单步 AST 语法预检。
3. **大型图谱全量渲染 (vis-network)**：
   - 当节点数超过 50 个（包含所有文献、假说、Run、产物）时，物理引擎初次稳定布局耗时略长，建议默认按 Project 进行子图过滤。

---

## 3. What users don't understand (用户容易感到困惑的设计)

1. **Experiment Protocol 与 Run 实例的区别**：
   - 初次使用的科研人员常把“实验方案（设计图纸）”和“单次物理运行（带具体指标的执行记录）”混淆，需要在 UI 上加深“方案 vs 运行”的卡片层级指引。
2. **Artifact 与 Evidence 的界限**：
   - 用户往往不清楚为什么产生了分析图表 (Artifact) 还需要提取为 Evidence 才能支撑 Conclusion，需在图谱和面板中强调“数据产物 → 提炼观点证据 → 支撑结论”的科学方法论。

---

## 4. What users don't use (当前低频或被边缘化的功能)

1. **复杂的 JSON 参数手动配置框**：
   - 用户更倾向于通过表格或向导选择超参，而不愿意手写复杂的嵌套 JSON 字典。
2. **旧版 Streamlit 归档入口**：
   - 全功能 Vue 3 Scientific IDE 已经完全覆盖旧版能力，用户几乎不再访问 `app.py`。

---

## 5. What users repeatedly do manually (用户经常重复手动操作的痛点)

1. **手动将结论复制到外部笔记（如 Obsidian / Notion）**：
   - 科研人员每次沉淀完 Conclusion 和 Evidence 后，习惯性手动复制成 Markdown 粘贴到个人知识库。**（极强需求：Obsidian Vault 双链直导）**。
2. **反复微调图表标题与配色**：
   - 目前 Matplotlib 自动生成的图表样式较固定，用户常常需要手动下载数据并在 Excel/Origin 重新绘图。

---

## 6. What AI gets wrong (AI 容易推断错误的地方)

1. **多数据表隐式业务主键判断**：
   - 当两个数据表的列名不完全一致（如 `patient_id` 与 `sub_id`）且没有元数据标注时，基于字符串相似度的自动关联可能出现假阳性，必须由用户二次确认。
2. **无结构化异常的隐式逻辑错误**：
   - 如果代码没有抛出异常（Exit 0）但是逻辑算错（如均值计算漏除了分母），Debugger 无法仅凭 Traceback 识别，需要引入断言（Assertion）检测机制。

---

## 7. What data should never leave local machine (绝对禁止离机的敏感资产)

1. **未发表的实验原始数据 (Raw CSV / Parquet)**：
   - 商业机密、临床患者数据与未发表实验测量结果严禁发送至任何云端第三方 LLM。
2. **本地环境路径与系统凭证**：
   - 虚拟环境可执行文件路径、本地文件绝对路径、API 密钥只能在本地沙箱使用，不可记录在任何云端日志。

---

## 8. What users want AI to remember (用户希望 AI 深度记住的内容)

1. **被证伪的假说与失败的实验参数**：
   - 例如 “动态边更新在 $k > 20$ 时发生过平滑”，在后续生成实验代码时坚决不再重复该错误区间。
2. **课题特定的评价指标与 Baseline 命名**：
   - 用户定义的基线模型缩写与特定评估指标口径（如 `F1-Macro`、`AUC-ROC`）。

---

## 9. What users don't want AI to remember (用户不希望 AI 混淆记录的内容)

1. **调试过程中的临时语法报错**：
   - 比如手误打错变量名引发的 `NameError`，不需要记录进科研记忆长期沉淀。
2. **跨项目的无关文献片段**：
   - 切换项目后，严禁串入上一个课题的特定领域词汇。

---

## 10. V2.5 核心输入总结

基于上述验证，V2.5 的核心演进方向已非常清晰：
1. **Obsidian Vault 双向链接适配器 (P0)**：自动生成标准 Frontmatter + `[[Wikilinks]]` Markdown 文档；
2. **纯本地离线大模型支持 (P0)**：一键连接本机 Ollama / llama.cpp，满足科研数据 100% 不离机诉求；
3. **PDF 可视化双栏划词切片组件 (P1)**：提供直观的 PDF.js 阅读与划词即切片体验；
4. **实验多组超参批量扫描与网格对比 (P1)**。
